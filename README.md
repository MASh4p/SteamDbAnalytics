# SteamDB Analytics

Локальное приложение для разбора магазина Steam: собирает карточки игр, считает сегменты (жанры, теги, форматы) и показывает, где спрос выше конкуренции. Интерфейс на Blazor Server, данные лежат в SQLite на этой машине.

Это не публичный SteamDB и не кабинет издателя. Охват и «шанс успеха» — оценки по отзывам и онлайну, а не продажи.

## Что умеет

- **Обзор** — сводка по уже собранной базе и короткие выводы.
- **Игры и топы** — списки с сортировкой по отзывам, качеству, приросту и онлайну.
- **Теги и жанры** — размер сегмента, медиана отзывов, тренд.
- **Для разработчика** — карта возможностей (квадранты спроса и конкуренции), ниши, форматы, пары тегов, факторы и проверка идеи.
- **Разработчики** — сводка по студиям и издателям из собранных карточек.
- **Моя игра** — слежение за AppID: позиции и собственные ежедневные снимки.
- **Сбор данных** — профили QuickStart, Daily, Deep и добор карточек. Сбор вежливый (паузы между запросами) и продолжается с места остановки.
- Экспорт таблиц в Excel.

Пока глубокий сбор не закончен, доля «успешных» игр завышена: в базе ещё мало игр без отзывов.

## Стек

| Проект | Роль |
| --- | --- |
| `src/SteamDB.Core` | Модель, статистика, метрики, отчёты. Без HTTP и БД. |
| `src/SteamDB.Infrastructure` | SQLite (EF Core), клиент Steam, фоновый сбор, экспорт. |
| `src/SteamDB.Web` | Blazor Server, MudBlazor, ApexCharts. |
| `tests/SteamDB.Tests` | xUnit: парсеры и статистика. |

.NET 10. HTTP-клиент ходит в витрину Steam (AngleSharp разбирает страницы). Ключи Data Protection и лог пишутся рядом с базой; строки с API-ключом в лог не попадают.

## Запуск

Нужен [SDK .NET 10](https://dotnet.microsoft.com/download).

```bash
dotnet run --project src/SteamDB.Web
```

Сайт открывается на `http://localhost:5080`. При первом старте создаётся база `steamdb.sqlite`. Кнопка «Обновить» в шапке запускает быстрый сбор, страница «Сбор данных» — остальные профили.

Тесты:

```bash
dotnet test
```

Решение: `SteamDB.slnx`.
